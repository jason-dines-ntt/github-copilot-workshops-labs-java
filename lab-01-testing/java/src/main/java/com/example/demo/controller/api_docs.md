# Employee API Documentation

## Overview

This REST API provides endpoints for managing employee records in the system. It supports full CRUD (Create, Read, Update, Delete) operations on employee data.

### Available Endpoints
- **GET** `/api/employees` - Retrieve all employees
- **GET** `/api/employees/{id}` - Retrieve a specific employee by ID
- **POST** `/api/employees` - Create a new employee
- **PUT** `/api/employees/{id}` - Update an existing employee
- **DELETE** `/api/employees/{id}` - Delete an employee

### Request Format
- All requests must include the header: `Content-Type: application/json`
- POST and PUT requests require a JSON body with employee data
- Employee object structure:
  ```json
  {
    "name": "string",
    "surname": "string",
    "email": "string"
  }
  ```

### Response Format
- All successful responses return HTTP 200 OK
- Response bodies are in JSON format
- GET endpoints return employee object(s) with auto-generated ID
- DELETE endpoint returns no content (void)
- All endpoints include logging for entrada (input) and salida (output)

## Endpoints

### 1. Get All Employees

**Endpoint:** `GET /api/employees`

**Description:** Retrieves a list of all employees in the system.

**Curl Command:**
```bash
curl -X GET http://localhost:8080/api/employees \
  -H "Content-Type: application/json"
```

**Expected Behavior:**
- Returns HTTP 200 OK
- Response body contains a JSON array of employee objects
- Each employee object includes: id, name, surname, and email
- Returns an empty array if no employees exist

**Example Response:**
```json
[
  {
    "id": 1,
    "name": "John",
    "surname": "Doe",
    "email": "john.doe@example.com"
  },
  {
    "id": 2,
    "name": "Jane",
    "surname": "Smith",
    "email": "jane.smith@example.com"
  }
]
```

---

### 2. Get Employee by ID

**Endpoint:** `GET /api/employees/{id}`

**Description:** Retrieves a specific employee by their unique identifier.

**Curl Command:**
```bash
curl -X GET http://localhost:8080/api/employees/1 \
  -H "Content-Type: application/json"
```

**Expected Behavior:**
- Returns HTTP 200 OK if employee exists
- Response body contains a JSON object with employee details
- Returns null or error if employee with specified ID doesn't exist

**Example Response:**
```json
{
  "id": 1,
  "name": "John",
  "surname": "Doe",
  "email": "john.doe@example.com"
}
```

---

### 3. Create Employee

**Endpoint:** `POST /api/employees`

**Description:** Creates a new employee in the system.

**Curl Command:**
```bash
curl -X POST http://localhost:8080/api/employees \
  -H "Content-Type: application/json" \
  -d '{
    "name": "John",
    "surname": "Doe",
    "email": "john.doe@example.com"
  }'
```

**Expected Behavior:**
- Returns HTTP 200 OK on successful creation
- Response body contains the created employee object with assigned ID
- Validates employee data before saving
- ID is automatically generated by the system

**Example Response:**
```json
{
  "id": 1,
  "name": "John",
  "surname": "Doe",
  "email": "john.doe@example.com"
}
```

---

### 4. Update Employee

**Endpoint:** `PUT /api/employees/{id}`

**Description:** Updates an existing employee's information.

**Curl Command:**
```bash
curl -X PUT http://localhost:8080/api/employees/1 \
  -H "Content-Type: application/json" \
  -d '{
    "name": "John",
    "surname": "Doe",
    "email": "john.updated@example.com"
  }'
```

**Expected Behavior:**
- Returns HTTP 200 OK if update is successful
- Response body contains the updated employee object
- Returns null if employee with specified ID doesn't exist
- Updates name, surname, and email fields
- ID cannot be changed

**Example Response:**
```json
{
  "id": 1,
  "name": "John",
  "surname": "Doe",
  "email": "john.updated@example.com"
}
```

---

### 5. Delete Employee

**Endpoint:** `DELETE /api/employees/{id}`

**Description:** Deletes an employee from the system.

**Curl Command:**
```bash
curl -X DELETE http://localhost:8080/api/employees/1 \
  -H "Content-Type: application/json"
```

**Expected Behavior:**
- Returns HTTP 200 OK on successful deletion
- No response body (void return type)
- Employee is permanently removed from the system
- Subsequent requests for the deleted employee will return null or error

**Example Response:**
```
(No content)
```

---

## Notes

- Base URL: `http://localhost:8080`
- All endpoints use JSON format for request/response bodies
- Content-Type header should be set to `application/json`
- Logging is enabled for all endpoints (entrada/salida logs)
